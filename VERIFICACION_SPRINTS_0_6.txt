SPRINT 2 - AUTH SANCTUM
=======================

Objetivo:
Validar register, login, logout y rutas protegidas.

1. Ejecuta los tests de autenticacion:

   docker compose exec -T backend php artisan test --filter=AuthApiTest

   Debe terminar con tests en PASS.

2. Verifica que /api/user sin sesion esta protegido:

   curl.exe -s -i http://localhost:8000/api/user

   Debe responder:
   HTTP 401 Unauthorized
   {"message":"Unauthenticated."}

   Si responde HTTP 500 con "Route [login] not defined", reinicia backend:

   docker compose restart backend

   Luego repite el curl. Debe devolver 401, no 500.

3. Verifica login manual:

   Primero confirma que el usuario demo existe:

   docker compose exec -T backend php artisan tinker --execute "echo DB::table('users')->where('email', 'test@example.com')->count();"

   Debe devolver:
   1

   Abre:
   http://localhost:5173

   Ingresa:
   email: test@example.com
   password: password

   Debes entrar al dashboard.

   Si no entra desde el navegador:
   - Refresca con Ctrl+F5.
   - Cierra y abre de nuevo http://localhost:5173.
   - Borra cookies/local storage de localhost si el navegador quedo con una
     cookie vieja de una prueba anterior.
   - Verifica que escribiste exactamente:
     test@example.com
     password

   Si aparece "ApiError" con HTTP 502:
   - Significa que el frontend/Vite no logro hacer proxy al backend.
   - Reinicia el frontend para que tome el proxy Docker:

     docker compose up -d frontend

   - Verifica que el proxy ya responde con 401 y no con 502:

     curl.exe -s -i http://localhost:5173/api/user

   - Debe devolver:
     HTTP 401 Unauthorized
     {"message":"Unauthenticated."}

   Prueba tecnica de login por API:

   $session = New-Object Microsoft.PowerShell.Commands.WebRequestSession
   $originHeaders = @{ Origin = 'http://localhost:5173'; Accept = 'application/json' }
   try { Invoke-WebRequest -Uri http://localhost:5173/sanctum/csrf-cookie -WebSession $session -Headers $originHeaders | Out-Null } catch { }
   $xsrf = ($session.Cookies.GetCookies('http://localhost:5173') | Where-Object { $_.Name -eq 'XSRF-TOKEN' } | Select-Object -Last 1).Value
   $headers = @{ Origin = 'http://localhost:5173'; Accept = 'application/json'; 'X-XSRF-TOKEN' = [System.Net.WebUtility]::UrlDecode($xsrf) }
   $body = @{ email = 'test@example.com'; password = 'password' } | ConvertTo-Json -Compress
   $login = Invoke-RestMethod -Uri http://localhost:5173/api/auth/login -Method Post -WebSession $session -Headers $headers -ContentType 'application/json' -Body $body
   $login.user.email

   Debe imprimir:
   test@example.com

4. Verifica logout:

   En el frontend, usa el boton de salir/cerrar sesion.

   Debes volver al login.

Criterio de exito S2:
- AuthApiTest pasa.
- /api/user sin sesion responde 401.
- Puedes iniciar y cerrar sesion desde la UI.

PROBLEMAS FRECUENTES
====================

1. El frontend no carga:

   docker compose ps
   docker compose logs -f frontend

2. El backend no responde:

   docker compose ps
   docker compose logs -f backend

3. Productos devuelve 0:

   Probablemente el volumen de MariaDB quedo viejo o los tests tocaron la base.
   Recarga desde cero si puedes borrar datos locales:

   docker compose down -v
   docker compose up -d --build

4. Error de conexion a DB desde Docker:

   En backend/.env debe estar:
   DB_HOST=mariadb
   DB_DATABASE=bagg_autopartes

5. Error de conexion a DB ejecutando Artisan desde el host:

   Si ejecutas php artisan directamente fuera del contenedor, cambia
   temporalmente backend/.env a:

   DB_HOST=127.0.0.1

   Luego limpia config:

   cd backend
   php artisan config:clear

6. Login no entra:

   Verifica que el seeder haya creado el usuario:

   docker compose exec -T backend php artisan tinker --execute "echo DB::table('users')->where('email', 'test@example.com')->count();"

   Debe devolver:
   1
